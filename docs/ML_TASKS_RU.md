# Что могут делать ML-инженеры в этом репозитории

Точную задачу ставит тот, кто нанимает команду (преподаватель, заказчик или руководитель). Этот файл только показывает, что даёт репозиторий. Английская версия: [ML_TASKS.md](ML_TASKS.md). Таблица для работы: [ML_TASKS_RU.xlsx](ML_TASKS_RU.xlsx).

## Коротко

«Доработать ботов» — это **одна из возможных** задач, но не единственная. Сейчас в игре нет обученных моделей. Всё, что выглядит как интеллект, написано вручную (правила и случайность). Работа ML-инженеров — заменить или дополнить эти части обученными и доказать, что стало лучше.

## Что здесь называется «ботами»

| Где | Что это | Как работает сейчас |
|---|---|---|
| `test/balance.test.ts`, `npm run balance` | Боты-игроки, проходят игру целиком, пишут `docs/BALANCE.md` | Ручные стратегии и случайность |
| `test/players20.test.ts`, `npm run playtest`, `scripts/playtest50.mjs` | 20-50 ботов с разными стилями, которые задействуют всю игру | Случайный выбор с учётом стиля (`STYLES`) |
| `dev/playtest/` | Сохранённые результаты прогонов | Файлы JSON |
| `src/dating.ts` | Персонажи приложения знакомств и их ответы | Правила и готовые фразы |
| `src/platform/telemetry.ts` | События, о которых игра может сообщать | Счётчики, без модели |

## Что нужно для старта

- Репозиторий (доступ есть) и Node 20+: `npm install`, затем `npm run local` для игры и `npm test` для проверки.
- Состояние и сцены: `src/engine.ts`, `src/content/`, `src/scenes-ru-*.ts`.
- Код ботов и их файлы результатов из таблицы выше.
- Письменное определение слова «лучше» от того, кто поставил задачу (какая цифра должна вырасти).

## Правила для любой модели в игре

- Она не должна ломать тесты (`npm test`) и ограничения размера (`test/perf.test.ts`): большие файлы моделей загружаются по требованию, а не в первой загрузке.
- Никаких личных данных в обучающих данных. В файлах прогонов только выдуманные игроки.
- Контент для России должен соответствовать российскому закону (например, без однополых отношений и запрещённых тем); модели, которые пишут текст, нужен фильтр и тесты на него.

## Задачи для обучения и сильного портфолио

Тот же список лежит в таблице [ML_TASKS_RU.xlsx](ML_TASKS_RU.xlsx): у каждой задачи есть исполнитель, статус и заметки.

**Стартовые задачи (недели 1-2)**
1. Поиграть в игру 30 минут и записать 10 наблюдений, как первый тестировщик.
2. Запустить `npm run balance` и `npm run playtest`, написать сводку на страницу: редкие концовки, места, где игроки застревают.
3. Сделать дашборд результатов ботов (`docs/BALANCE.md`, `dev/playtest/`): деньги по дням, доли концовок.

**Данные и анализ**
4. Разбить ботов-игроков на группы по поведению (богатые, бедные, учёба, нарушители) и описать каждую группу.
5. Найти самые тяжёлые дни или сцены (больше всего потерь здоровья или денег) и предложить исправления.
6. Составить план, что игра должна записывать об игроках (`src/platform/telemetry.ts`), без личных данных.

**Построение моделей**
7. Предсказывать концовку по первым 10 дням (хороший первый настоящий ML-проект).
8. Бот-имитатор: копирует выбор хороших игроков.
9. Бот с обучением с подкреплением: максимизирует счёт игры (нужна чёткая награда).
10. Рекомендатор выбора: подсказывает лучшее действие для текущего состояния, питает карточку «Следующий шаг» (`src/nextstep.ts`).

**Язык (русский и английский)**
11. Скрипт, который находит английский текст, оставшийся в русском режиме.
12. Безопасная генерация текста с фильтром запрещённых тем и российского закона.
13. Тесты качества диалогов: вежливо, по теме, законно.

**Инженерные привычки**
14. Писать тесты для каждой модели.
15. Соблюдать ограничения размера: загружать модели по требованию (`test/perf.test.ts`).
16. Проверять код друг друга через pull request.
17. Писать короткий отчёт по каждой задаче: что пробовали, что сработало, одна цифра как доказательство.

**Рекомендуемый план:** недели 1-3 задачи 1-7; недели 4-6 задачи 8-10 с привычками из 14-17.
